# 기본은 경량 모드 (2026-11-16 파일럿 후 변경)

파일럿(눈 지문 4문항)에서 서브에이전트 맹검 풀이를 5회 돌렸더니 약 51만 토큰이 들었고, 잡은 결함은 정답 선지 자체 모순·길이 단서 정도였다. 아래 "경량 모드"를 기본으로 하고, 아래쪽 전체 파이프라인은 필요할 때만 쓴다.

## 경량 모드 (기본)
1. 본체가 설계와 초안을 한 번에 쓴다(청사진 단계 생략, 정답 위치만 미리 정함).
2. 스크립트로 점검한다(토큰 0): 선지 길이(정답−오답평균 ±5자 이내), 정답 분포, 연속 정답, 배점, `<보기>` 개수, 정답 선지의 자체 모순 문구.
3. 무료 모델(FreeLLMAPI, gemini-3.5-flash) **1회**로 맹검 풀이: 정답이 다르거나 확신 낮음 → 그 문항만 본체가 재검토. 전부 정답·고확신이면 "쉬울 수 있음"으로 표시하고 정답 선지만 손질.
4. 서브에이전트는 쓰지 않는다. 복수 정답·근거 모호가 의심되는 문항 1~2개에만 예외로 쓴다(1회 약 10만 토큰).
5. 수정은 한 번만. 재검증은 하지 않는다(필요하면 사용자가 요청).

# 기말 모의고사·n제 제작 워크플로 (품질↑ 난이도↑ 토큰 효율)

목표: 정답 선지가 지문 한 문장으로 "보이지 않는" 고난도 문항을, 비싼 토큰은 **설계와 최종 손질·검수 판정**에만 쓰고 나머지는 스크립트·무료 모델·독립 검수자로 분산한다.
단위: **지문 세트 1개 = 작업 1건**(지문당 4문항, 모의고사는 세트 묶음). 세트마다 파일 하나(`sets/<번호>-<지문명>.md`)로 남겨 어느 세션에서든 이어간다.

## 담당 나누기
| 단계 | 담당 | 하는 일 | 토큰 |
|---|---|---|---|

## 맹검 판정 기준 (4→5)
- 풀이자 둘 다 **근거 한 문장으로 쉽게 정답** → 너무 쉬움: 정답 선지를 재작성(최우선 원칙 위반).
- 풀이자가 **정답 없음/둘 이상**이라고 주장 → 지문과 대조해 복수 정답·근거 없음 여부 판정, 수정.
- 한 명만 맞힘, 근거 설명이 지문 두 곳 이상을 종합 → 목표 난이도.
- "애매함"은 목표가 아니다: 정답은 지문 근거로 **하나만** 방어 가능해야 한다.

## 토큰 아끼는 규칙
1. 해설지(1MB)·지침서(110KB)·지문 PDF를 통째로 읽지 않는다. 항상 해당 세트 분량만 발췌해서 준다.
2. 한 세트 = 새 서브에이전트(깨끗한 맥락)로 병렬 처리. 세트 간 결과를 본체가 다시 읽지 않는다(요약표만 받는다).
3. 무료 모델에는 **지문 원문과 청사진만** 보낸다. 해설지 원문·지침서 전문은 보내지 않는다(외부 무료 서비스는 학습에 쓸 수 있음).
4. 무료 모델 초안은 정답 판정에 쓰지 않는다(정답·난이도 판정은 본체와 맹검 풀이자만).
5. 한 번 통과한 세트는 다시 열지 않는다. 수정 요청이 오면 해당 문항만.
6. 반복 작업(형식 점검, 정답 분포, PDF 조판)은 스크립트로 고정해 둔다(`tools/`).

## 진행 순서
1. **파일럿 1세트**(v2에서 빠졌던 지문 중 하나)로 0~7을 끝까지 돌려 품질과 토큰을 확인한다. 무료 초안이 쓸모없으면 2단계를 빼고 본체가 직접 쓴다.
2. 빠진 4개 지문(프랭클 / 아도르노·표현주의 / 유엔해양법 / 플로티노스) 확장.
3. v2 모의고사 35문항 **맹검 재검수**(4~5단계만 적용).
4. 필요하면 파트별 고난도 n제 추가.
