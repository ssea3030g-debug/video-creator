# 문항 제작 작업 흐름 (개편판, 2026-11-22)

> 이전 방식(작업 시작 때마다 지침서 7종 약 250KB 전부 읽기 + 서브에이전트 맹검 풀이)을 바꾼다.
> 기본 원칙: **만들 때는 `핵심-틀.md`만, 지침 전체는 사용자가 요청할 때만.**

## 단계 한눈에
| 단계 | 하는 일 | 읽는 것 | 담당 | 토큰 |
|---|---|---|---|---|
| 1 제작 | 설계 카드 → 문항·해설 작성 | `핵심-틀.md` + 해당 지문 | Claude | 중간 |
| 2 오류 검수 | 정답 오류·복수 정답·근거 없음·계산·사전 뜻풀이·형식 수치 | 만든 문항 + 지문 | 스크립트 + 무료 모델 + Claude(걸린 문항만) | 적음 |
| 3 지침 검수 (선택) | **"지침 검수할까요?"라고 묻고**, 하라고 하면 지침 원문 전체로 대조 → 선지 다듬기 → 형식 맞추기 | 지침 원문 7종(해당 절) | Claude | 많음 |
| 4 PDF | md → 시험지 PDF | — | 스크립트 | 0 |

## 1단계: 제작
1. `핵심-틀.md`를 읽는다. **지침 원문은 열지 않는다.** 해설지(1MB)는 해당 지문 부분만 grep으로 발췌한다(원본 문항의 급소·밑줄 위치 확인용).
2. 회차 설계표를 먼저 쓴다(표만): 세트 × 문항 번호 × 유형 × 파트 × 슬롯(M1~M8) × 목표 L × 배점 × 정답 번호.
   - 슬롯 할당량(핵심 틀 8장)과 L 분포 목표(L3+ 55%, L4 세트당 1+)를 설계표에서 먼저 맞춘다.
3. 문항마다 **설계 카드 한 줄**을 쓰고 나서 선지를 쓴다(`난이도-상향-프로토콜.md` 1장).
4. 정답 선지를 먼저 쓰고, 오답 넷을 서로 다른 기법으로 쓴다. 해설은 핵심 틀 9장 형식.
5. **새 세션 규칙 유지**: 처음에는 세트 1개만 완성해 보여주고, 허락받은 뒤 나머지를 만든다("전부 만들어"라고 하면 예외).

## 2단계: 오류 검수 (항상 한다, 범위는 오류만)
지침을 지켰는지는 보지 않는다. **시험지로 낼 수 없는 결함**만 잡는다.
1. 스크립트(토큰 0)
   - `check_set.py`: 배점 합, 정답 분포·연속, 선지 길이·정답 길이 순위.
   - 정답표 ↔ 해설 제목 번호 일치, 문항 수, <보기> 개수.
2. 무료 모델 풀이 1회(FreeLLMAPI, gemini-3.5-flash): **지문 + 문항만** 보낸다(정답표·해설·L 태그 제외). 정답과 근거 문장, 확신도를 받는다.
   - 정답이 다르거나, "정답 없음/둘 이상"이라고 하거나, 확신이 낮은 문항 → Claude가 그 문항만 지문과 대조.
   - 한도(429)로 약한 모델이 풀었으면 "검증 약함"으로 보고한다.
3. Claude 확인(걸린 문항 + 아래 항목만)
   - 정답이 지문 근거로 **하나만** 방어되는가, 틀린 선지가 정확히 한 군데만 틀리는가.
   - 날짜·수치 선지 재계산(기산일 포함).
   - 어휘 뜻풀이 표준국어대사전 대조.
4. 고치는 건 **결함이 있는 문항만, 한 번만.** 재검증은 사용자가 요청할 때.
5. 보고: 결함 목록과 고친 내용. "검토 완료"라고 쓰지 않는다(지침 준수는 보지 않았으므로).
6. 보고 끝에 묻는다: **"지침서 기준 검수(선지 다듬기·형식 맞추기)도 할까요?"**

## 3단계: 지침 검수 (사용자가 하라고 할 때만)
1. 지침 원문을 해당 절만 순서대로 연다: 출제분석 지침서(★, 3~5장, 8장, 11·12장) → 파트별 사고방식(해당 파트) → 모의고사용 지침서 → 난이도 기준·보완 → 실수 유의사항 → 최상 메커니즘 체크리스트.
2. 문항별 위반표를 만든다(v6 검수보고서 형식: 문항 / 위반 / 근거 절).
3. 선지 다듬기: 위반 문항의 정답·오답을 고친다. 길이대·뼈대·지문 순서·교차 선지 위치를 맞춘다.
4. 형식 맞추기: 배점·L 태그·정답표·해설을 함께 고치고 `check_set.py` 재실행.
5. 새로 지적된 실수는 `실수-유의사항.md`에 일반 규칙으로 추가하고, 그 규칙이 제작 단계에서 필요하면 `핵심-틀.md`에도 한 줄 반영한다.

## 4단계: PDF
- `tools/make_exam_pdf.py`(모의고사 v2 양식). 한글 폰트 `fonts-nanum`, `fonts-noto-cjk` 필요. 1~2쪽만 그림으로 확인.
- exam-app에 올릴 때는 `exam-app/public/papers/`에 넣고 `index.json`에 추가.

## 토큰 절약 규칙
1. 제작 때 지침 원문 금지(핵심 틀만). 원문 내용이 필요하면 해당 절만 grep으로 발췌.
2. 서브에이전트 맹검 풀이는 쓰지 않는다(파일럿에서 5회에 약 51만 토큰). 예외: 복수 정답이 의심되는데 무료 모델과 Claude 판단이 엇갈리는 문항 1~2개.
3. 무료 모델에는 지문 원문과 문항만 보낸다. 해설지·지침서 전문은 보내지 않는다.
4. 통과한 세트는 다시 열지 않는다. 수정 요청은 해당 문항만.
5. 반복 점검은 스크립트로 고정(`tools/`).
